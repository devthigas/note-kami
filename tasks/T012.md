## 1. Objetivo Técnico
Implementar o controller de solicitação e verificação de links mágicos com proteção contra enumeração de contas e estabelecimento seguro de sessão.

## 2. Arquivos Impactados
| Arquivo | Ação | Descrição |
| :--- | :--- | :--- |
| `app/controllers/magic_links_controller.rb` | **Create** | Ações new, create, sent e verify |
| `app/views/magic_links/new.html.erb` | **Create** | Formulário de solicitação de link de acesso |
| `app/views/magic_links/sent.html.erb` | **Create** | Tela de confirmação de envio do link |
| `config/routes.rb` | **Modify** | Rotas para magic_links (new, create, sent, verify) |

## 3. Passo a Passo de Implementação
1. Configure as rotas em `config/routes.rb`: `resources :magic_links, only: [:new, :create]` com rotas de coleção para `get :sent` e `get :verify`.
2. Em `app/controllers/magic_links_controller.rb`, ignore o filtro de autenticação: `skip_before_action :require_authentication`.
3. Na ação `create`: localize ou instancie o usuário por `email_address`. Gere o token e envie via `MagicLinkMailer.sign_in_link(user, token).deliver_later`. Redirecione para `sent_magic_links_path`.
4. Na ação `verify`: busque o usuário via `User.find_by_token_for(:magic_link, params[:token])`.
5. Se o usuário existir: atualize `user.update!(last_sign_in_at: Time.current)`, chame `start_new_session_for(user)` e redirecione para `dashboard_path`.
6. Se o token for inválido ou expirado: redirecione para `new_magic_link_path` com alert apropriado.

## 4. Critérios de Aceite (Definition of Done)
- [ ] Ação `create` redireciona para confirmação de envio sem revelar se a conta existia previamente.
- [ ] Token válido autentica o usuário e grava a sessão no cookie assinado.
- [ ] Token expirado ou corrompido é rejeitado com mensagem explicativa.
