## 1. Objetivo Técnico
Implementar testes automatizados de unidade e de requisição (TDD) para validar a geração de tokens de Magic Link com expiração estrita de 15 minutos, consumo único, sincronização da foto de perfil via OAuth (`profile_photo`) e criação de sessão.

## 2. Arquivos Impactados
| Arquivo | Ação | Descrição |
| :--- | :--- | :--- |
| `test/models/user_test.rb` | **Create** | Testes unitários para generates_token_for :magic_link e atributo opcional profile_photo |
| `test/controllers/magic_links_controller_test.rb` | **Create** | Testes de integração para solicitação e verificação de token |
| `test/controllers/oauth_controller_test.rb` | **Create** | Testes de integração para callback OAuth e sincronização de profile_photo |

## 3. Passo a Passo de Implementação
1. Em `test/models/user_test.rb`, crie teste verificando que `user.generate_token_for(:magic_link)` gera um token alfanumérico não-vazio e que `profile_photo` é opcional (`allow_nil: true`).
2. Crie teste verificando que `User.find_by_token_for(:magic_link, token)` retorna o usuário correto dentro de 15 minutos.
3. Crie teste de expiração verificando que após `travel 16.minutes`, o método retorna nil.
4. Crie teste de invalidação por reuso: após `user.update(last_sign_in_at: Time.current)`, o token antigo deve ser invalidado.
5. Em `test/controllers/magic_links_controller_test.rb`, teste `POST /magic_links` com email válido gerando e enfileirando e-mail.
6. Teste `GET /magic_links/verify?token=VALOR_VALIDO` configurando cookie de sessão e redirecionando para dashboard.
7. Teste `GET /magic_links/verify?token=TOKEN_EXPIRADO` redirecionando para `/login` com flash de erro.
8. Em `test/controllers/oauth_controller_test.rb`, teste que `GET /auth/google/callback` persiste a URL `picture` retornada pelo provedor em `user.profile_photo` (e mantém `nil` sem erros quando o provedor não enviar foto).

## 4. Critérios de Aceite (Definition of Done)
- [ ] Testes cobrem geração, expiração em 15 minutos e consumo único do token.
- [ ] Testes de OAuth validam o armazenamento automático de `profile_photo` a partir do payload do provedor OAuth.
- [ ] Testes de controller validam respostas HTTP 302 com redirecionamento e integridade de cookie.
- [ ] Testes executam sem falhas (`bin/rails test`).
