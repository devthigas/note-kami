## 1. Objetivo Técnico
Implementar testes de unidade e de Action Cable channels para garantir permissões de acesso ao stream da nota, verificação de papéis (editor vs viewer) e difusão correta dos eventos de presença.

## 2. Arquivos Impactados
| Arquivo | Ação | Descrição |
| :--- | :--- | :--- |
| `test/models/note_collaborator_test.rb` | **Create** | Testes para o modelo join NoteCollaborator |
| `test/channels/note_channel_test.rb` | **Create** | Testes para subscrição, autorização e broadcasts no NoteChannel |

## 3. Passo a Passo de Implementação
1. Em `test/models/note_collaborator_test.rb`, teste a unicidade do par `[note_id, user_id]`.
2. Teste a validação que impede que o proprietário da nota seja cadastrado como seu próprio colaborador.
3. Teste a restrição de papéis (`editor` e `viewer`).
4. Em `test/channels/note_channel_test.rb`, teste subscrição de usuário autorizado conectando-se a `note_42`.
5. Teste rejeição de subscrição (`assert_has_stream` vs `assert_no_stream` / `assert_rejected`) para usuários sem permissão.
6. Teste a ação `appear` e `disappear` transmitindo evento `presence_update` com a lista de avatares ativos (incluindo `profile_photo` e `avatar_color`).

## 4. Critérios de Aceite (Definition of Done)
- [ ] Testes de modelo asseguram integridade de colaboração e papéis.
- [ ] Testes de canal validam segurança (rejeitam acessos não-autorizados).
- [ ] Eventos de presença produzem payloads JSON conformes com a especificação em `cable-channels.md` (incluindo `profile_photo`).

## 5. Validação e Testes
### Validação Automatizada:
```bash
bin/rails test test/models/note_collaborator_test.rb test/channels/note_channel_test.rb
```

### Validação Manual:
Execute os testes de canal e certifique-se de que os broadcasts são simulados sem depender de Redis.
