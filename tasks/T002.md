## 1. Objetivo Técnico
Configurar isolamento multi-database em SQLite3 para desacoplar as operações de dados primários da aplicação das operações de alta frequência de escrita de websockets (Solid Cable), cache (Solid Cache) e filas (Solid Queue).

## 2. Arquivos Impactados
| Arquivo | Ação | Descrição |
| :--- | :--- | :--- |
| `config/database.yml` | **Modify** | Declarar bancos primary, cable, cache e queue com WAL mode |
| `config/cable.yml` | **Modify** | Configurar adapter solid_cable apontando para o banco cable |

## 3. Passo a Passo de Implementação
1. Abra `config/database.yml` e configure os bancos para `development` e `test` com: `primary` (`storage/development.sqlite3`), `cable` (`storage/development_cable.sqlite3`), `cache` (`storage/development_cache.sqlite3`) e `queue` (`storage/development_queue.sqlite3`).
2. Defina `timeout: 5000` em cada base para evitar `SQLite3::BusyException` sob concorrência.
3. Edite `config/cable.yml` e defina `adapter: solid_cable` com `connects_to: { database: { writing: :cable } }`.
4. Execute `bin/rails db:prepare` para provisionar todas as estruturas de dados.

## 4. Critérios de Aceite (Definition of Done)
- [ ] `config/database.yml` possui configurações isoladas para as quatro bases.
- [ ] `config/cable.yml` referencia o adaptador solid_cable e a conexão com a base `cable`.
- [ ] `bin/rails db:prepare` executa sem erros e cria os arquivos em `storage/`.

## 5. Validação e Testes
### Validação Automatizada:
```bash
bin/rails db:prepare
test -f storage/development.sqlite3 && test -f storage/development_cable.sqlite3 && echo 'Multi-DB OK'
```

### Validação Manual:
Inicie `bin/dev` e confira nos logs que as conexões com as bases isoladas foram estabelecidas sem falhas.
